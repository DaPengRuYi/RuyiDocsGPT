## 开篇：一个真实场景 / 痛点
> 占位：怎么把开源项目变成"我们自己的"产品，又不至于以后没法同步上游、变成孤儿分叉。用 RuyiDocsGPT 自己的诞生史开场。

## 本章目标
- 看懂 RuyiDocsGPT 是怎么从 DocsGPT 纯二开出来的（隔离层、改动清单、同步 SOP）；
- 掌握"改皮不改骨"的二开方法论，知道改哪些、不碰哪些；
- 亲手做三开：把 RuyiDocsGPT fork 成你自己品牌的知识库工厂。

## 本章小节（10 节）
1. 纯二开的原则：保留主流程，只改"皮"和"默认值"，先不动核心逻辑
2. 复盘：RuyiDocsGPT 是怎么从 DocsGPT 生出来的（基线快照 + upstream 只 fetch 永不 push）
3. 隔离层设计：为什么所有二开资产都住在 `ruyi/`（同步上游几乎零冲突）
4. 改动清单：每改一个上游文件登记一行（`ruyi/docs/UPSTREAM_SYNC.md` 实物讲解）
5. 品牌化与中文化实录：根 README 门面、前端标题、Hero 主标题、默认中文包，改了哪几处、为什么只改这几处
6. 默认配置改造：国产模型 + 本地向量 + 一键脚本怎么固化成 `ruyi/` 资产
7. 上游同步 SOP：fetch → 看差异 → cherry-pick/merge → 评测把关 → 才进 main
8. 轮到你了：fork 公开仓，做你自己的三开（换品牌名、换默认语料、换演示数据）
9. 三开验收：换牌后仍能跑通第 7 章问答，评测不退化
10. 控制风险：可回滚、清单化、永不推上游、密钥不进 git

## 核心概念（大白话）
> 占位：纯二开 vs 重写 vs 提炼内核；"改皮不改骨"为什么能一直同步上游；二开族谱（DocsGPT → RuyiDocsGPT → 你的三开）。

## 实战步骤
> 占位：带读者 fork 公开仓 → 换品牌（README/前端标题/中文包）→ 换默认语料 → 登记改动清单 → 跑通问答 + 评测，录一段自己品牌的演示。

## 关键代码 / 命令 / 配置
> 占位：UPSTREAM_SYNC 改动清单表实例、upstream remote 配置（push 禁用）、品牌替换点清单、`ruyi/` 层结构。

## 常见坑
> 占位：改太多核心逻辑导致没法同步上游；二开资产散落各处（应集中 `ruyi/`）；改了上游文件忘登记清单；误推 upstream。

## 本章小结
> 占位：二开的护城河不是改得多，是改得少而清楚；清单化 + 隔离层 + 评测把关，三开照做就不失控。
