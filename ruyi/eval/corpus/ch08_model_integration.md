## 开篇：一个真实场景 / 痛点
> 占位：同一套 RAG，7B 模型答得一堆乱码，72B 立马干净——模型选错，前面白干。

## 本章目标
- 把"接什么模型、怎么接、接不通怎么办"讲透；
- 覆盖国产 API（硅基流动）、本地模型、OpenAI 兼容三条路；
- 讲清模型大小对问答质量的影响。

## 本章小节（10 节）
1. DocsGPT 的 provider 体系：`llm/providers/` 注册表 + `LLMCreator`
2. OpenAI 兼容是万能钥匙：一个 base_url + 一个 key 就能接国产模型
3. 接硅基流动：`LLM_PROVIDER=openai` + `OPENAI_BASE_URL` + `LLM_NAME`
4. 密钥怎么管：只进环境变量 / `.env`，绝不写进代码、绝不进 git
5. 一个真实坑：本机的 Anthropic key 其实是会话令牌，不能直连 API
6. anthropic provider 为什么别直接用：它还在用已退役的旧接口
7. 本地模型路线：Ollama / 本地推理端点怎么接
8. 大模型 vs 小模型：为什么 Qwen2.5-7B 答崩、换 72B 就干净
9. Embedding 也要选对：远程维度坑与本地方案的取舍
10. 一张"模型接入决策表"：什么场景用什么模型
