## 开篇：一个真实场景 / 痛点
> 占位：先给读者看成品长什么样——上传资料、问答、显示引用来源的一套私有系统。

## 本章目标
- 说清全书要造的东西：RuyiDocsGPT / 如意知识库工厂；
- 讲清为什么选 DocsGPT 做底座、什么叫"纯二开"；
- 对 0→1 的终点有画面感。

## 本章小节（8 节）
1. 先看成品：能上传、能问答、能显示引用来源的私有系统长什么样
2. 为什么不从零手写：完整 RAG 产品要哪些零件
3. 为什么选 DocsGPT 当底座：成熟、开源、模块齐、可二开
4. 什么叫"纯二开"：保留产品形态，改中文、改品牌、换模型、做部署、做教学
5. 为什么不走"提炼轻量内核"这条老路（一次诚实的方向复盘）
6. RuyiDocsGPT 的三种交付形态：本地运行版、教学演示版、可部署服务版
7. 技术选型底线：国产模型 API + 本地向量 + 数据不外发
8. 全书路线图与你最终会拥有的东西

## 核心概念（大白话）
> 占位：完整 RAG 产品 vs 玩具 demo；纯二开 vs 从零写 vs 提炼内核。
