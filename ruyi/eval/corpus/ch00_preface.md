# 前言：这本书想带你做一件真事

大家好，我是张大鹏。

先说说我为什么要写这本书。

这几年 RAG 特别火，讲 RAG 的资料也满天飞。可我发现一个尴尬：**看完的人很多，真能把一套知识库问答系统做出来、还能交给别人用的人，很少。** 大部分教程要么在讲理论，一上来就是向量、余弦相似度、稠密检索，看完你还是不知道从哪下手；要么就是一个跑起来就没了的玩具 demo，离"能用的产品"差着十万八千里。

真正缺的，是有人带你把一个**完整的、开源的、能落地的 RAG 产品**，从跑通、拆解、改造，一路做到能部署、能交付、能讲成课。

这本书就是干这件事的。

## 我们要一起做出什么

一句话：**把开源项目 DocsGPT，纯二开成一套属于我们自己的知识库问答系统，我给它起名叫"如意知识库工厂"，代号 RuyiDocsGPT。**

这不是我拍脑袋想出来的。写这本书之前，我先让整套流程在自己机器上实打实跑了一遍：本机没装 Docker，我改成本地原生把它拉起来；大模型接的是国产的硅基流动，向量用的是本地中文模型；然后我导入了几份中文资料，连问了十一个问题，**每一个都答对了，而且每条答案都带着出处**。连过程里踩的坑、报的错、怎么修的，我都记下来了。这本书里的命令、配置、报错、结果，绝大多数都是这么真跑出来的，不是我编的。

## 这本书和别的 RAG 教程有什么不一样

| | 普通 RAG 教程 | 这本书 |
|---|---|---|
| 拿什么练手 | 手写玩具 / 纯 API 调用 | 完整开源产品 DocsGPT 纯二开 |
| 做到哪一步 | 停在"能跑一个问答" | 一直做到"能部署交付给别人" |
| 有没有主线 | 零散知识点 | 一条 0→1 主线：RuyiDocsGPT |
| 中文友好吗 | 大多是英文 / OpenAI | 国产模型、中文资料、国内网络环境 |
| 学完剩下啥 | 看过就忘 | 能讲的课、能跑的项目、能改的源码、能交付的产品 |

## 学完你能做到四个"能"

- **能讲**：拿着每章配套的讲义，把 RAG 和这套系统讲清楚给别人听；
- **能跑**：在自己机器上把系统跑起来，接好模型、导入资料、问出带引用的答案；
- **能改**：读懂源码，完成中文化、品牌化、换模型这些二开改造，做出你自己的 RuyiDocsGPT；
- **能部署**：把它部署到服务器，交给客户或学员，还能做基本的运维。

## 这本书怎么读

全书 **12 章**，串成一条从"搞懂 RAG"到"交付产品"的完整主线：

- **第 1–2 章**：先把"为什么要做知识库""我们要做个什么系统"讲透，不碰代码。
- **第 3–4 章**：把如意知识库工厂在你本机跑起来，再读懂它的结构。
- **第 5–8 章**：吃透主链路——文档入库、向量检索、问答引用、模型接入。
- **第 9–11 章**：搞懂二开方法论、把工厂改成你自己的，再做部署、评测和运维。
- **第 12 章**：收口，把前面的东西拧成"能讲的课 + 能交付的产品"。

每一章我都按同一个节奏走：一个真实痛点开场，讲清本章要干什么，把概念用大白话说明白，然后动手实战、贴真命令、讲我踩过的坑，最后给你留一个能上手的练习和一个能沉淀成产物的作业。**每章结尾你都会亲手做出一个真东西**，十二章下来，你手里就是一整套自己的知识库产品。

## 给你提个醒

- 这本书默认面向**国内同学**：国产模型 API、中文资料、国内网络那些坑，我都照实讲。
- 我不吹"生产环境直接能上"。该说的二开风险我照说，但都会告诉你**怎么控制**。
- 书里所有涉及密钥的地方，一律只写变量名，绝不出现真实密钥——这个习惯你从第一天就要养成。

好，废话不多说，我们从第 1 章开始，先把"RAG 到底解决什么问题"这件事，用最朴素的话讲明白。
