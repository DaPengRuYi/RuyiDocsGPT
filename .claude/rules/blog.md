# 博客写作规范

> 适用于本项目相关的所有博客。博客会公开发布，按本规范执行。
> 本项目（如意知识库工厂 / RuyiDocsGPT）是开源项目 **DocsGPT**（私有知识库 RAG 问答系统）的纯二开。博客主要讲：DocsGPT 是什么、怎么跑通、怎么二开、RAG 评测与踩坑心得。整体就像**张大鹏在分享自己研究和二开这个项目的技术博客**。
> 本项目还有一本配套书《大鹏 RAG 实战：如意知识库工厂》（`D:\notes\RuyiBookCourse\图书\AI 开发\大鹏 RAG 实战：如意知识库工厂\`），博客选题可与书稿章节互相喂料，但博客独立成文，不预设读者看过书。

## 位置与命名
- **博客成品统一放 `D:\notes\RuyiWriter\作品\博客\<年>年\<月>月\` 下**：一篇一个 `.md` 文件（扁平，**不要一篇一个子目录**）；图放该月共享的 `images\`，文件名加博客序号前缀防多篇撞名（如 `005_eval_report.png`），正文用 `images/005_xxx.png` 引用。在 RuyiWriter 按年月集中管理；**本仓库不存放博客成品**，只保留本写作规范（`.claude/rules/blog.md`）。
- 文件名：`序号_标题.md`，三位序号（顺延该月已有序号）。
- 正文 H1 必须与文件名标题一致，不使用副标题。

## 标题规范（重点）
标题直接决定搜索与点击，逐条执行：

1. **每篇标题必须包含中文品牌名「如意知识库工厂」**（铁令，不可省略）；建议同时带技术名 DocsGPT 或 RAG 以吃搜索流量。
2. **长度约 20 字**（中文，含技术名后可略放宽），别太长，过长会被搜索引擎截断，也显啰嗦。
3. **搜索关键词前置**：高搜索量的词靠前。本项目强相关词：`RAG`、`DocsGPT`、`知识库`、`私有部署`、`本地知识库`、`AI 问答`、`大模型幻觉`、`开源二开`。一个标题最好能组合出多个长尾词。
4. **结尾带钩子**，三选一：疑问句引好奇 / 反差痛点前置 / 故事感。
5. **可适度借力背书/触发词**：GitHub star 数、真实评测数据（命中率/幻觉率）、实测结果等，但**适度，严禁关键词堆砌**，可读性第一。
6. **不做标题党**：标题承诺的，正文必须兑现。

> 定标题前的标准动作：先参考同领域爆款标题规律，拟 3 到 4 个候选让用户挑，不直接拍板。

## 开场白（每篇必须）
每篇博客正文的**第一句**（标题之后、正文开头），固定用口头禅开场：

> OK，OK，大家好，欢迎大家来到大鹏 AI 教育，我是张大鹏。

紧接着再进入正文。语气自然口语，像开直播 / 开课时跟观众打招呼那样。

## 内容与口吻
- **第一人称、第一视角**，全程以**我**（张大鹏）的身份分享**所见所闻**，像专家一样讲，有观点、有判断，不堆砌套话。
- **贴近真实场景举例**：多用直播间、课堂、给学员讲解、看回放复盘这类我真实会经历的场景来打比方，让抽象的东西落地、有画面感。
- **简体中文**。
- **所有技术论断必须对照真实代码核实**，不臆测、不照搬 README 概括；引用文件路径要准，优先用本仓库真实实现佐证：上游主流程在 `application/`（api / parser / retriever / llm / worker），二开层在 `ruyi/`（一键脚本 / 回归评测 / 上游同步文档）。评测数据引用 `ruyi/eval/` 的真实跑分，不编数字。
- **发表级质量**：避免 AI 味（空泛排比、套话、emoji 堆砌）。
- 面向读者的正文**禁破折号 `——`、禁直角引号**，需要强调一律用加粗。

## 配图
- **每篇最多 3 张插图**（宁缺毋滥，图是为讲清内容服务的）；封面不单独做，从这 3 张插图里自选。
- 图放该月共享的 `images\`（见「位置与命名」），正文用相对路径 `images/xxx.png` 引用。
- 优先用项目真实截图（代码、运行输出、评测报告、问答带引用的界面、启动日志），别用无关配图。
